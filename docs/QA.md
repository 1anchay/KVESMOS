# Приёмочная проверка

## Автоматически

`flutter analyze`; `flutter test --coverage`; `flutter test integration_test/app_test.dart -d <test-device>`. Последняя команда очищает только данные OrbitWords на выбранном устройстве; запускайте на выделенном эмуляторе. CI конфигурация подготовлена, но запуск GitHub Actions не выполнялся.

Unit / repository tests: 20 уроков / 200 валидных заданий, нормализация, XP/дедупликация, ошибки, SM-2, серии, офлайн-прохождение всех уроков, реальное закрытие и повторное открытие SQLite-файла, атомарность, черновик, устаревшие записи, удаление/восстановление пакета и локальная очистка.

Sync tests используют fake transport: потеря сети, потеря подтверждения после commit, слияние двух устройств, защита owner и режим гостя. Они не доказывают доступность hosted Supabase или корректность deployed RLS.

Widget tests: онбординг, первый ответ, выход/продолжение, навигация по страницам и масштаб 200%. Android integration: весь урок с 10 типами, реальная native SQLite, XP и словарь. Аудио/микрофон в интеграционном тесте не используются, для соответствующих заданий выбран текстовый режим.

## Проверить вручную перед выпуском

- Установка на физические Android и iPhone, первый запуск без интернета, TTS с установленным/отсутствующим английским голосом.
- Для каждого задания: правильный/неправильный ответ, неограниченный повтор, закрытие приложения между вводом и проверкой, быстрое двойное нажатие.
- Принудительный stop после правильного ответа и до анимации; перезапуск без потери XP и позиции.
- Отказ микрофона, повторный отказ, отсутствие speech engine, работа on-device, смена аудиовыхода.
- Уведомления: отказ, разрешение, выключение, перезагрузка телефона, энергосбережение, отсутствие лишних повторов.
- TextScale 200%, TalkBack/VoiceOver, горизонтальная ориентация, клавиатура, маленький экран; контраст, экранная навигация, reduced motion.
- Нехватка места, ошибка открытия базы, большой журнал; приложение не должно удалять данные само.
- Пропуск дня и переход через полночь, смена часового пояса.

## Облачная приёмка

1. Развернуть миграцию и delete-account в тестовом проекте. Запустить `supabase/tests/rls.sql` через psql с ON_ERROR_STOP.
2. Зарегистрироваться с гостевыми данными, подтвердить email, войти. Проверить безопасное сохранение сессии после перезапуска.
3. На двух устройствах выполнить разные уроки офлайн. Подключить сеть: обе истории объединяются, повторный sync не дублирует XP.
4. Оборвать соединение после отправки, затем повторить. Очередь очищается только после подтверждения.
5. С другим пользователем попытаться читать/писать чужие события через REST; доступ должен быть запрещён. В UI смена owner требует очистки.
6. Восстановить пароль через email/deep link, обновить пароль. Проверить истёкшую и повторно использованную ссылку.
7. Удалить аккаунт из приложения: auth user и события исчезают, локальный прогресс очищается. Старый токен не возвращает историю и не добавляет события.
8. Проверить восстановление после сетевой ошибки при удалении; UI не должен утверждать успех до ответа сервера.

## Безопасность

В клиенте только публичный ключ, RLS включён, service role только в Edge Function. Нет рекламных SDK. Не логировать пароли/токены/аудио. Не хранить signing keys в git. Локальная база не является зашифрованным сейфом. Custom URL scheme и email-потоки требуют production-hardening. Проверки зависимостей, privacy manifests и аппаратных разрешений не заменять ссылкой на успешные unit tests.
