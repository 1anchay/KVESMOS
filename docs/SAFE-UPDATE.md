# Безопасное обновление проверочных APK

Android applicationId остаётся `dev.orbitwords.orbitwords`, схема SQLite — 1. Данные не сбрасываются при обновлении материалов: новые сессии получают новый пакет, начатые продолжают собственный сохранённый пакет. Позиция объяснения сохраняется в дополнительной настройке сессии. XP, события, инвентарь и авторизация не мигрируют в другую базу.

## Постоянная подпись

Android Preview использует `KVESMOS_PREVIEW_KEYSTORE_BASE64` из GitHub Actions Secrets. В него зашифрованно передан существующий локальный debug-keystore владельца. Ключ не печатается в логах, не коммитится и не прикладывается к APK. Приватная копия сохранена у владельца вне репозитория. Если секрет отсутствует, workflow отказывается публиковать APK со случайной подписью. Доступ к изменению workflow и Secrets должен оставаться только у доверенных участников проекта.

Gradle получает путь к восстановленному ключу явно через `KVESMOS_PREVIEW_KEYSTORE`, независимо от системного каталога Android на runner. Перед публикацией CI проверяет ожидаемый SHA-256 сертификата: `b8c558730dd20651119dd74b014b31ff51f076af208198dc79e05e51a0dca8be`. При несовпадении артефакт не публикуется.

В артефакте есть `app-debug.apk`, `SHA256SUMS.txt` и `signing-certificate.txt`. SHA-256 файла проверяет целостность, fingerprint сертификата — принадлежность ключу. Это разные проверки.

**Старые APK из Actions, подписанные случайным ключом другого runner, могут быть несовместимы.** Из публичного сертификата нельзя восстановить приватный ключ. Постоянная подпись исправляет последующие сборки, но не делает старые разные подписи одинаковыми. Не удаляйте приложение и не используйте новый package ID для обхода конфликта.

Основание: [Android app signing](https://developer.android.com/studio/publish/app-signing), [GitHub Secrets API](https://docs.github.com/en/rest/actions/secrets#create-or-update-a-repository-secret).

## Проверка и установка

Нужны Python 3.10+, Android SDK с platform-tools/build-tools, включённая USB-отладка и разрешённое устройство. Укажите точный serial из `adb devices`.

```powershell
python tool/install_preview.py PATH_TO_APK --sdk C:/Users/vtar4/OrbitWordsSDK --serial DEVICE_SERIAL
```

Без флага `--install` скрипт только проверяет пакет, версию и сертификат. Для установки:

```powershell
python tool/install_preview.py PATH_TO_APK --sdk C:/Users/vtar4/OrbitWordsSDK --serial DEVICE_SERIAL --install --backup-dir .tools/update-backups
```

Скрипт сравнивает сертификаты установленного и нового APK, запрещает понижение versionCode, останавливает приложение, сохраняет приватные данные и прежний APK в новую папку и запускает только `adb install -r`. При несовпадении подписи или недоступной резервной копии обновление прекращается. Резервное копирование через `run-as` рассчитано на проверочные debug-сборки; для production требуется отдельный пользовательский экспорт. Каталог резервных копий может содержать персональные данные и токены — не публикуйте его.

После обновления откройте карту, незаконченный урок и профиль. Если Android отказывает в установке, оставьте текущую версию на устройстве. Никогда не запускайте `adb uninstall` или `pm clear` ради обновления. Диагностический `integration_test/app_test.dart` с очисткой данных не предназначен для пользовательского телефона.

Если приложение уже удалялось, восстановление возможно только из настоящей совместимой копии или ранее настроенной синхронизации. Наличие новой сборки само по себе потерянные данные не восстанавливает.
