# Игровая архитектура

## Решение

Flutter остаётся оболочкой, учебным UI и доступными оверлеями. Для одной пространственной сцены испытать Flame внутри Flutter. В главе сейчас меняются фон и текст, а у StarChart уже есть полезный прототип pan/zoom. StarChart можно оставить на Flutter, пока не понадобятся общий мир, слои, несколько актёров и единый игровой такт. [StarChart](../../lib/ui/star_chart.dart) · [Flame Camera & World](https://docs.flame-engine.org/latest/flame/camera.html)

| Вариант | Выигрыш | Цена и условие |
|---|---|---|
| Flutter / CustomPainter | Текущая карта, портреты, переходы, доступность. Небольшой дифф. | Для свободного перемещения придётся отдельно реализовать камеру, диспетчер объектов, hit testing и lifecycle. Держать на ограниченных поверхностях. |
| Flame GameWidget | Камера и мир со временем delta, координатами, слоями, спрайтами и обработкой событий. Flutter остаётся для семантики, текста и уроков. | Провести A/B на одном мостике. Только одна активная игровая сцена, загрузка по маршруту, освобождение атласов при выходе. Версию закрепить после замеров. |
| Runtime 2D-скелета | Компактные состояния, направленный взгляд, независимые действия, потенциально меньше кадров в APK. | Сложнее интеграция с текстурным стилем и профилированием. Первый этап запекает клипы из рига, переход к runtime — по фактическому бюджету. |
| Отдельный нативный движок | Имеет смысл при обязательном 3D и исчерпанном 2D-рендерере. | Дублирование lifecycle, управления памятью, навигации, клавиатуры и доступности. Сейчас нет доказанного требования. |

## Границы ответственности

- `lib/domain`, `LearningRepository`, `RewardsRepository` и `AppController` сохраняют доменные решения, ID, установку уроков, награды и базу. Значимые действия приложения проходят через существующие транзакции. [Репозиторий уроков](../../lib/data/repository.dart) · [Награды](../../lib/data/rewards_repository.dart)
- Игровая папка `lib/game` владеет камерой, слоями, состоянием актёров, интерактивными зонами и загрузкой атласов. Описания локаций содержат ID, порядок слоёв, точки контакта, посадочные координаты, дверные связи и позицию камеры. Поскольку это данные представления, они не используют хранилище курса.
- `WorldSnapshot` передаёт язык, доступные узлы, текущий урок, состояния главы, настройки движения и озвучки. Обновляется только на доменное событие. `WorldAction` передаёт hit-zone, взаимодействие, выбор пункта и выход. На выходе сцена посылает намерение открыть урок. Обычная проверка доступности, установленности и черновика решает маршрут через GoRouter.
- `ChapterRepository` работает с версионированным DTO: `chapterId, courseId, stage, targetLessonId, startedAfter, sessionId, completionEventId`. Записывает одно пройденное сюжетное действие условной транзакцией по ожидаемой стадии, повторный callback идемпотентен. Учебное завершение определяется сохранённым событием после начала главы для этого курса и целевого занятия. Для уже завершившего весь курс допускается специальный сюжетный повтор с явно определённой политикой. ID прогресса главы и политика разрешения конфликта должны попадать в валидатор резервной копии. [Текущий черновик](../../lib/ui/beacon_chapter.dart) · [Импорт](../../lib/data/progress_transfer.dart#L756)
- `SceneAudio` использует существующий LearningAudio и его playback. Один идентификатор реплики/актёра и поколение запроса защищают от поздних callbacks. Тишина, текст и альтернативный ответ доступны при отказе аудио или речи.
- `SceneHost` при скрытии, потере фокуса, сворачивании и reduced motion приостанавливает мир и аудио. В reduced motion перемещения завершаются безопасным статичным кадром, команды остаются доступны. Для каждой игровой точки существует Flutter-оверлей с семантикой и альтернативный список. Камера не получает тап из открытого оверлея.

Проверка границы — 1000 тиков сцены после прогрева дают ноль операций записи SQLite и ноль глобальных notifyListeners. После возврата из урока мир восстанавливается из одного снимка. Повтор открытия карты и сцены не начисляет XP.
