# KVESMOS — короткие задачи для следующих запусков Codex

Каждую задачу запускайте **отдельно**, после успешного завершения предыдущей; полный контекст в `04_codex/CODEX_MASTER_PROMPT.md` и дизайнерских документах.

## Этап 2: ребрендинг и UI
Продолжай **существующий** Flutter-проект, ничего не сбрасывай. Прочитай `00_READ_FIRST/START_HERE.md` и `02_design/BRAND_GUIDE_CURRENT.md` в пакете KVESMOS. После подтверждения завершённого этапа микрофона внедри только display name KVESMOS, брендовые цвета, улучшение карты и экранов урока/результата/профиля. Не меняй applicationId, SQLite, Supabase-ID, не начинай сундуки. Выбранный Орби — снизу справа на листе иконок, не другие варианты. Проверки по затронутым областям, краткий отчёт.

## Этап 3: персонажи
После принятия UI создай простой каталог персонажей по `02_design/CHARACTERS.md` и `03_data/kv_catalog_draft_v2.json`. Не выдумывай спрайты: листы — только референсы. Начни с 2–3 героев, сохраняй конфигурационную расширяемость. Пикси ещё нет, имя профессора-лиса не утверждено. Проверки + отчёт.

## Этап 4: бесплатные сундуки
В существующем Flutter-проекте реализуй локальную систему первых косметических сундуков по `02_design/REWARDS_SPEC.md`, начав с `explorer` и 1 экипируемого слота. SQLite миграция без потери данных; уникальные ID выдачи, идемпотентная запись выпадения, бездубликатный инвентарь, тест на повторное открытие и офлайн. Не вводи оплату/рекламу. Не обещай реальный серверный sync без проверки.

## Этап 5: оформление и награды
Расширь инвентарь на 20 предметов, 3 сундука, 4 редкости, видимые фактические вероятности и пропускаемую анимацию. Только после утверждения отдельной графики; временные заглушки явно помечать как временные. Отдельные тесты вероятностей, миграций, восстановления после прерывания.
