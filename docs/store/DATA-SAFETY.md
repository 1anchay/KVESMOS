# Данные и разрешения — рабочая ведомость

Это техническая основа заполнения форм, не готовая юридическая декларация. Ответы в консоли должны соответствовать конкретному подписанному артефакту и production-инфраструктуре.

| Категория | Поведение кода | Что подтвердить до отправки |
|---|---|---|
| Профиль и прогресс | SQLite на устройстве: имя, события, XP, результаты, словарь, настройки, черновики | Нет ли стороннего сбора в итоговой конфигурации; правила локального удаления |
| Email и авторизация | Только при подключённом Supabase: email/пароль в Auth, сессия в secure storage | Регион, оператор, сроки хранения, логи, subprocessors и реальные настройки сервера |
| История обучения | Supabase learning_events при добровольной синхронизации; RLS по пользователю | Тест двух аккаунтов, удаление с каскадом, backup retention; не обещать перенос всех локальных настроек |
| Микрофон | RECORD_AUDIO для необязательного говорения; текстовая альтернатива | Поведение реального провайдера ASR и on-device режима; нельзя заявлять отсутствие передачи ОС без проверки |
| Озвучка | Встроенные записи либо системный TTS | Системный голос может требовать загрузки/сетевого сервиса; проверить пять локалей |
| Уведомления | POST_NOTIFICATIONS по разрешению; локальные напоминания | Отказ, отзыв разрешения, перезагрузка, тихие часы |
| Загрузка после перезагрузки | RECEIVE_BOOT_COMPLETED восстанавливает расписание/виджет | Нет лишнего фонового поведения; проверить реальный телефон |
| Интернет | INTERNET для настроенного облака | Подтвердить конечные адреса, HTTPS, отсутствие service-role ключей в клиенте |
| Реклама/аналитика | Рекламные и аналитические SDK в текущей реализации не добавлены | Повторить аудит зависимостей финальной сборки |

Без SUPABASE_URL/SUPABASE_ANON_KEY приложение работает локально и показывает, что облако не подключено. Это не подтверждает готовность регистрации: её нельзя рекламировать до проверки сервера. Публичный anon/publishable key не является service-role ключом; привилегированные ключи допустимы только на сервере.

Удаление: клиент запрашивает подтверждение, функция проверяет токен и удаляет только вызывающего пользователя. Локальная очистка разрешена лишь после успешного статуса и `deleted: true`. Требуются реальные тесты ошибок сети, токена, повторного запроса и каскада БД; unit-тест не доказывает серверное удаление.

Владелец должен предоставить публичные HTTPS URL политики и внешнего запроса удаления, подтвердить юридические сведения, аудиторию и условия хранения. Email поддержки — vtar4a@gmail.com. Публичные страницы пока отсутствуют.

Политики: https://support.google.com/googleplay/android-developer/answer/10144311 и https://support.google.com/googleplay/android-developer/answer/10787469 . Не выбирать «данные не собираются» автоматически при включённом облаке.
